## 下载哪个

| 文件 | 装到哪 |
| :--- | :--- |
| `App-SakuraRemote.zip` | **手机**。解压后得到 `SakuraRemote-release.apk` 再安装 |
| `plugin-sakura.remote-1.2.5.zip` | **电脑**。解压后把 `sakura.remote` 目录放到 Sakura 的 `plugins/user/` 下 |
| `MANUAL.md` | 完整使用手册，参考用 |

两个都要装：插件装电脑，App 装手机。

> **升级注意**：如果装过旧版 App，因为签名相同可以直接覆盖安装；
> 插件直接覆盖 `plugins/user/sakura.remote/` 目录即可，
> 配置和聊天记录在 `data/plugins/sakura.remote/`，不会被覆盖。

## 使用前提

先安装并跑通官方 [Sakura Desktop Pet](https://github.com/Rvosy/sakura)，
本项目是它的插件与配套 App，自身不含对话模型和语音合成。

- 电脑：Windows 10 / 11
- 手机：Android 10 及以上（Android 14+ 最稳妥）

完整安装步骤见 `MANUAL.md`，已知问题与版本兼容说明见仓库首页的 README。

## v1.2.5 更新内容

### 修好了：拖动时立绘一直抽搐

根因是一个**正反馈回路**（三个问题叠加，逐个修掉）：

**1) 用 clientX/clientY 做参照 → 回路**

视口长在悬浮窗里面，我们一移动窗口，视口参照就跟着动 ——
同一个物理手指位置读出的 `clientY` 就变了，据此再算新的窗口位置，
形成正反馈。实测拖动中 `client − screen` 的差值有 252 种取值，
单帧位移高达 47px/6ms（人手不可能做到）。

**修法**：改用 `screenX/screenY`（屏幕绝对坐标，不随窗口移动），回路被切断。

**2) 增量累加把手指抖动积分了**

原来是每帧 `x += dx`。手指有约 ±15px 的高频抖动，累加会把它**积分**进去，
窗口在 428px 跨度里持续来回漂（实测方向反转 693 次）。

**修法**：改成绝对定位 ——
`窗口位置 = 按下时的窗口位置 + (手指现在的位置 − 手指按下的位置)`。
抖动不再累积，手回原点窗口也回原点。

**3) 位移的线程调度有竞态**

`Choreographer.getInstance()` 必须在主线程调用，而拖动回调跑在 JavaBridge 线程；
另外「是否已排队」的标志跨线程读写会永久卡住。

**修法**：位移在桥线程即时累加，主线程用自重新调度的 Runnable 合并刷新，
状态用 `AtomicBoolean` —— 不再有跨线程标志。

### 附带

- 拖动期间跳过窗口尺寸重算与 resize 后的位置夹取（那两处也会抵消拖动位移）
- 拖动期间中立「按住放大」反馈（避免缩放与拖动互相干扰）

### 实测

| 指标 | 修复前 | 修复后 |
| :--- | :--- | :--- |
| 单帧位移 >30px 的次数 | 59 / 838 | **1 / 210** |
| 最大单帧位移 | 47px / 6ms | **31.8px / 8ms** |
| 参照系漂移取值数 | dx 165 / dy 252 | dx 58 / dy 121 |

单次 `moveTo` 的跟手精度：手指 +100 CSS px → 窗口 100.0 CSS px。
